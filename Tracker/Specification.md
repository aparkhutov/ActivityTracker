## Архитектурная спецификация проекта Tracker
Единый документ верхнеуровневого описания архитектуры, логики работы и форматов данных фонового трекера активности Windows.
## 1. Цель системы
Разработать Tracker – легковесное фоновое приложение для ОС Windows (без отображения интерактивного окна, с интеграцией в системный трей), которое с заданным интервалом (N секунд) опрашивает состояние операционной системы и записывает структурированные данные об активности пользователя в CSV-файлы. Данные накапливаются локально и используются встроенным HTTP-сервером для отдачи в Web-интерфейс дашборда.
## 2. Архитектура и жизненный цикл

* Процесс сборщика (ActivityTracker.exe): запускается в контексте текущего пользователя, работает в фоновом режиме, управляет логикой записи.
* Синхронизация инстансов: предотвращение повторного запуска трекера реализовано через механизм системного захвата эксклюзивного файла блокировки ActivityTracker_<username>.lock с флагом FILE_FLAG_DELETE_ON_CLOSE.
* Хранилище данных: папка на жестком диске (по умолчанию %LOCALAPPDATA%\ActivityTracker), внутри которой создаются плоские CSV-файлы.

## 3. Формат хранения данных (CSV)
Каждый файл содержит записи только за одни системные сутки и для одного конкретного пользователя.

* Имя файла: <YYYY-MM-DD>-<username>.csv (например, 2026-07-31-aparkhutov.csv).
* Ротация файлов: при смене даты в процессе работы трекер автоматически закрывает старый дескриптор файла и создаёт новый для текущей даты.
* Структура: файл не имеет заголовка (Plain Data). Данные дописываются в конец файла (режим ab) с флагом совместного чтения без блокировки записи (_SH_DENYNO). Разделителем полей является запятая (,), разделителем строк — символ перевода строки (\n).

## Состав полей (строгий порядок)

   1. Дата: Локальная дата системы в формате YYYY-MM-DD.
   2. Время: Локальное время с миллисекундами в формате HH:MM:SS.mmm.
   3. Секунды с начала суток: Количество секунд, прошедших с 00:00:00 (целое число от 0 до 86399).
   4. Тип сессии: Статус активности терминального подключения (console, rdp, off, unknown).
   5. Время бездействия (idle_seconds): Количество секунд с момента последнего ввода пользователя (мышь/клавиатура).
   6. Имя процесса (process_name): Имя исполняемого файла активного окна (например, chrome.exe). Если активное окно отсутствует или сессия закрыта (off) — поле пустое.
   7. Заголовок окна (window_title): Текст из заголовка активного окна. Если активное окно отсутствует или сессия закрыта (off) — поле пустое.

## Санитизация текстовых полей
Перед записью в файл поля process_name и window_title проходят обязательную очистку для сохранения целостности структуры CSV-документа:

* Все запятые (,) заменяются на точки (.).
* Все двойные кавычки (") заменяются на тильды (~).
* Символы перевода строк (\r, \n) заменяются на одиночные пробелы.

## 4. Алгоритмы сбора состояний ОС## Определение типа сессии и блокировки (Utils::GetConnectionStatus)
Использует Windows Terminal Services API (WTSQuerySessionInformationW):

   1. Через запрос WTSConnectState проверяется состояние текущей сессии. Если состояние не равно WTSActive, сессия считается неактивной/выключенной (off).
   2. Через запрос WTSSessionInfoEx проверяются флаги состояния сессии. Если флаги сигнализируют о блокировке рабочей станции (SessionFlags != WTS_SESSIONSTATE_UNLOCK), сессия считается заблокированной и трекер возвращает статус off.
   3. Через запрос WTSClientProtocolType определяется физический тип протокола: WTS_PROTOCOL_TYPE_RDP возвращает rdp, а WTS_PROTOCOL_TYPE_CONSOLE возвращает console.

## Определение бездействия (Utils::GetIdleSeconds)
Использует функцию Win32 API GetLastInputInfo(&lii). Количество секунд бездействия вычисляется по формуле:
$$\text{idle\_seconds} = \frac{\text{GetTickCount()} - \text{lii.dwTime}}{1000}$$ 
В случае системной ошибки или отсутствия данных возвращает 0.

## Определение активного процесса и окна (Utils::GetActiveWindowInfo)

   1. Функция GetForegroundWindow() запрашивает дескриптор текущего активного окна.
   2. Заголовок извлекается функциями GetWindowTextLengthW() и GetWindowTextW().
   3. Идентификатор процесса (PID) извлекается через GetWindowThreadProcessId().
   4. Трекер открывает процесс с флагом PROCESS_QUERY_LIMITED_INFORMATION и запрашивает полный путь через QueryFullProcessImageNameW().
   5. Обработка UWP-приложений: Если имя процесса совпадает с applicationframehost.exe, трекер запускает процедуру EnumChildWindows(), чтобы найти реальный дочерний рабочий процесс UWP-контейнера и извлечь полный путь.
   6. Функция возвращает пару std::pair<std::wstring, std::wstring>, где на первом месте всегда стоит полный путь к исполняемому файлу, а на втором — заголовок окна.

## Извлечение и умное кэширование иконок (ActivityTracker::PopulateIconCache)
  Для минимизации дисковой активности (`I/O overhead`) извлечение иконок оптимизировано с помощью хэш-сета в оперативной памяти:
   1. Инициализация (при старте): Метод `PopulateIconCache()` сканирует папку `%LOCALAPPDATA%\ActivityTracker\icons`, считывает имена всех существующих PNG-файлов и заполняет ими внутреннее хранилище `m_iconCache` (`std::unordered_set<std::wstring>`).
   2. В рабочем цикле: Из полученного от `Utils::GetActiveWindowInfo()` полного пути вычленяется короткое имя файла (например, `chrome.exe`), приводится к нижнему регистру и проверяется в кэше.
   3. Запись на диск: Если имени процесса нет в кэше, вызывается `Utils::ExtractAndSaveIcon`, которая вытаскивает иконку из полного пути через `SHGetFileInfoW`, конвертирует её в PNG с помощью Gdiplus и сохраняет на диск. После успешного сохранения имя процесса добавляется в `m_iconCache`.


## 5. Системные интерфейсы и многопоточность## Класс ActivityTracker (C++)
Класс инкапсулирует логику планирования циклов сбора данных и управление потоком. Поток сбора синхронизируется через Win32 события (CreateEventW).

class ActivityTracker
{
public:
    // Конструктор инициализирует базовые пути, интервалы и Win32 события синхронизации
    ActivityTracker(const std::wstring &folderPath, int intervalSeconds);
    ~ActivityTracker();

    void start();  // Основной рабочий цикл сбора данных (запускается в отдельном потоке)
    void stop(DWORD msTimeout); // Переводит статус в STOPPED, будит поток и ждет его завершения
    void pause();  // Временно приостанавливает сбор данных
    void resume(); // Возобновляет сбор данных
private:
    void PerformTrackingCycle(); // Один шаг опроса системы и записи строки в файл
    void Cleanup();              // Освобождение хэндлов Windows и закрытие файла
    void PopulateIconCache(); // Сканирование диска и заполнение кэша иконок в памяти
    
    std::wstring m_folderPath;
    int m_intervalSeconds;
    LONG m_status;               // Атомарный статус (RUNNING, PAUSED, STOPPED)
    
    HANDLE m_hEvent;             // Событие для прерывания ожидания таймера интервала
    HANDLE m_hShutdownEvent;     // Событие подтверждения остановки рабочего потока
    
    FILE* m_cachedFile = nullptr;// Дескриптор текущего открытого CSV-файла
    long m_cachedDayId = 0;      // Идентификатор дня для отслеживания ротации даты
    DWORD m_startWorkTicks = 0;  // Метка времени начала шага для компенсации задержек сбора
    
    std::unordered_set<std::wstring> m_iconCache; // Кэш извлеченных иконок процессов
};

## Жизненный цикл в main.cpp
Приложение инициализируется в классическом WinMain и разворачивает невидимое окно для интеграции с Shell-интерфейсами и подписками на системные события питания и сессий:

* Регистрация в Трей: Инициализирует иконку приложения через Shell_NotifyIconW(NIM_ADD, &g_nid).
* Завершение работы Windows: Оконная процедура WndProc перехватывает сообщения WM_QUERYENDSESSION и WM_ENDSESSION. При выключении или выходе из учетной записи Windows, трекер безопасно ставится на паузу, завершает текущую дисковую транзакцию записи, закрывает файл и корректно освобождает системные ресурсы в течение отведенного ОС лимита времени (тайм-аут 2500 мс).
* Управление Энергопотреблением: Сообщение WM_POWERBROADCAST с флагом PBT_APMSUSPEND переводит трекер в режим паузы, а PBT_APMRESUMEAUTOMATIC автоматически возобновляет мониторинг при пробуждении ПК.
