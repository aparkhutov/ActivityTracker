# Список задач по доработке проекта Tracker (C++)

В данном документе собраны критические исправления багов текущей реализации и новые архитектурные требования по оптимизации дисковой активности, энергосбережения и расширения аналитики.

---

## 📅 Этап 1: Реализация базовых фич (Оптимизация и Адаптивный интервал)

### 1.1 Закрытие файла при переходе в режим паузы (`STATUS_PAUSED`)
* **Задача:** В методе `ActivityTracker::pause()` добавить принудительное закрытие файла `m_cachedFile` и сброс кэша дня `m_cachedDayId = 0`, чтобы при просыпании системы транзакции начинались на чистом дескрипторе.

### 1.2 Фильтрация дубликатов при длительном статусе `off` (Дисковая дедупликация)
* **Задача:** Избежать раздувания CSV-файла тысячами одинаковых строк `off` во время блокировки экрана или сна ПК, сохраняя при этом базовый интервал опроса неизменным.
* **Алгоритм реализации:**
  * Добавить в класс `ActivityTracker` приватный счётчик подряд идущих состояний `off`: `int m_offSessionCount = 0;`.
  * В методе `PerformTrackingCycle()` получить текущий статус сессии через `Utils::GetConnectionStatus()`.
  * Если `session == L"off"`:
    * Увеличивать счётчик: `m_offSessionCount++;`
    * Если `m_offSessionCount > 2`, то **полностью пропускать** шаг формирования строки и записи в файл (делать `return` из метода).
  * Если статус сессии принимает любое другое значение (`console`, `rdp`, `unknown`):
    * Жестко сбрасывать счётчик в ноль: `m_offSessionCount = 0;`
    * Выполнять стандартную запись строки.
* **Результат для аналитики:** В CSV-файле при уходе ПК в сон запишется строго две строки `off` (например, в 18:00:00 и в 18:00:10). Следующая запись появится только утром в 09:00:00 со статусом `console`, когда пользователь разблокирует компьютер. WebUI легко посчитает разницу во времени между второй строкой `off` и строкой `console`.

## 🔥 Этап 2: Новые продвинутые фичи (Аналитика и Кэширование)

### 2.1 Детекция аудио-активности (Новое поле лога)
* **Задача:** Не ломать логику `idle_seconds`, но фиксировать, что компьютер «работает как медиа-центр» (идет созвон в Zoom, играет музыка или открыт видео-урок).
* **Реализация:** 
  * Использовать Windows Core Audio API (`IAudioMeterInformation`) для проверки наличия звукового потока в системе.
  * **Изменение формата CSV:** Добавить 8-е поле — `<is_audio_playing>` (`1` или `0`). Если пользователь физически в `idle`, но слушает лекцию — WebUI поймет, что это полезная активность.

### 2.2 Извлечение и умное кэширование иконок процессов
* **Задача:** Сохранять иконку запущенного процесса в формате `.ico` в папку `%LOCALAPPDATA%\ActivityTracker\icons` для отображения в дашборде.
* **Логика кэширования:**
  * В классе трекера завести `std::unordered_set<std::wstring> m_extractedIconsCache;`.
  * При старте приложения трекер сканирует папку `\icons` и забивает имена уже существующих файлов в этот хэш-сет (например, `chrome.exe`).
  * В цикле опроса, если для текущего `process_name` в кэш-сете **нет** записи:
    1. Через `ExtractIconW` или `SHGetFileInfoW` достаем хэндл иконки (`HICON`) из запущенного процесса.
    2. Сохраняем её в файл `\icons\process_name.ico`.
    3. Добавляем `process_name` в `m_extractedIconsCache`.
  * Если имя в кэше есть — шаг просто пропускается без обращений к диску.

### 2.3 Сжатие логов / Миграция прошлых дней в SQLite
* **Задача:** Текущий HttpServer парсит огромные CSV-файлы в памяти. Нужно настроить архивацию прошлых периодов.
* **Реализация:** 
  * Оставить текущий день в CSV (для высокой скорости записи `append` в фоне без блокировок бд).
  * При ротации даты (наступлении новых суток), перед тем как закрыть файл вчерашнего дня, фоновый поток трекера берет вчерашний CSV, парсит его и одной транзакцией переносит все записи в единую базу данных `history.db` (SQLite). После успешного импорта старый CSV-файл физически удаляется с диска.

## 🐛 Этап 3: Исправление критических багов (Bugfix)

### 3.1 Исправление Out-of-Bounds write в `Utils::GetActiveWindowInfo`
* **Проблема:** Строка резервируется под размер `length`, но в API `GetWindowTextW` передаётся `length + 1`. Происходит порча памяти (запись нуль-терминатора за пределы буфера `std::wstring`).
* **Решение:** Выделять `length + 1` символов, а после вызова делать `resize` до фактически скопированного количества.

### 3.2 Корректная обработка кириллических имен пользователей в `Utils.cpp`
* **Проблема:** Строгий ASCII-фильтр заменяет любые русские буквы в логине (например, `Иван`) на подчеркивания `____`. Из-за этого лог-файлы разных пользователей с кириллическими именами затирают друг друга.
* **Решение:** Разрешить в функции `Sanitize` пропуск символов из диапазона кириллицы.

### 3.3 Безопасный `worker_join()` при уничтожении окна в `main.cpp`
* **Проблема:** Вызов `worker_join()` после таймаута блокирует главный поток бесконечно, если рабочий поток завис на системном вызове Terminal Services. ОС принудительно аварийно завершает процесс.
* **Решение:** Заменить жесткий `g_worker->join()` на условную проверку, либо вызывать `detach()`, если поток не успел завершить работу в рамках лимита времени.

## 🛠 Этап 4: Безопасность инсталлятора

### 4.1 Защита от деструктивного удаления папок в `installer.cmd.txt`
* **Проблема:** Если пользователь ставит программу в Portable-режиме без создания изолированной папки (`FOLDER_CHOICE=n`), деинсталлятор выполнит `rmdir /s /q` родительского каталога и уничтожит всё его содержимое.
* **Решение:** В команду удаления в реестре зашивать `rmdir` только в том случае, если флаг `FOLDER_CHOICE` был равен `y`. Если `n`, то удалять строго один файл: `del /f /q \"%TARGET_DIR%\%EXE_NAME%\"`.
